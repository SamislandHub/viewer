# Viewer 项目交接

> 新会话接手时先读这份文档、`docs/DESIGN.md` 和 `README.md`，再继续开发。

## 目标

一个简单的 Agent 浏览器，网页运行在独立的 `WebContentsView` 中；支持虚拟鼠标与虚拟键盘，通过 Chromium 的可信输入管线操作页面，不移动真实系统光标，也不向页面注入 JavaScript。

## 当前架构

```
主窗口 (frame:false)
├─ 顶部单行工具栏：导航 ← → ↻ + 地址栏 + 打开控制台 + 窗口置顶 + 窗口按钮
├─ 左侧：垂直标签页（每个标签 = 独立 WebContentsView）
├─ 中间：当前标签的网页 WebContentsView
└─ 光标层：透明 WebContentsView，仅 34×28，贴在网页上一层

虚拟控制台 (frame:false, 独立窗口, 无 parent, 默认隐藏, 默认不置顶)
└─ 虚拟鼠标 / 虚拟键盘 / 资源分析
```

控制台通过工具栏 `▤` 开关；关闭后再次点击会重建窗口。网页原生模态框不会禁用控制台输入。

## 已完成的约束

- 不用 Playwright/Puppeteer 内核；只用 Electron 自带 Chromium。
- 不往网页注入 JS（`executeJavaScript`/`eval`/`dispatchEvent` 都没有用于页面操作；诊断时也只读）。
- 不碰真实系统光标：全部走 `sendInputEvent`，事件 `isTrusted=true`。
- `_blank` / `window.open` 转成新标签，不开新窗口。
- 虚拟光标：橙色、小巧、无文字；默认隐藏；窗口尺寸变化后自动隐藏；空白页不显示；每个标签独立状态。
- 点击分左键/右键，连击次数 1..10；有虚拟滚轮。
- 中文输入通过系统剪贴板 + Ctrl+V，已验证。
- 标签加载时显示旋转指示与进度条。

## 原生交互（当前状态）

- **文件选择**：`Page.setInterceptFileChooserDialog` + `Page.fileChooserOpened` → 应用内文件选择器 → `DOM.setFileInputFiles`，实测回填成功。必须由可信用户手势触发（虚拟鼠标点击即可），`executeJavaScript` 的 `input.click()` 不算。
- **alert / confirm / prompt**：标签页已设置 `disableDialogs: true`，不弹任何原生框。`alert` 立即返回，`confirm` 固定返回 `false`，`prompt` 返回 `null`。之前尝试过的 CDP 弹框接管、UIA/`BM_CLICK` 点击原生框均已移除。
- **确认分支注意**：如果业务依赖 `confirm()` 为 `true`，需要页面内自定义弹框，不能依赖原生 API。

## 资源分析

- 只用 `session.webRequest` 的 `onResponseStarted` / `onCompleted` / `onErrorOccurred`。
- **不要注册 `onBeforeRequest`**：在当前 Electron 版本中，仅注册该监听器就会让主窗口 renderer 永远加载不完（白屏）。
- 每标签保留最近 500 条，节流 200ms 推送到控制台。
- 不采集响应 body（需要 CDP，按边界未启用）。

## 指纹

- `app.userAgentFallback` + `session.setUserAgent`：UA 对齐内置 Chromium，去掉 `Electron/x.y.z`。
- CDP `Emulation.setUserAgentOverride`：`userAgentData.brands` 补 `Google Chrome`，对齐 platform / languages。
- 实测：`webdriver=false`、`vendor=Google Inc.`、`pdfViewerEnabled=true`、plugins 5 个（PDF 相关）均与 Chrome 一致。
- 仍无法改：`window.chrome.runtime`、`Notification.permission`（默认 `granted`）。

## 运行

```bash
cd <项目目录>
npm run dev
```

配置里已设置 `ELECTRON_ENTRY`、`NO_SANDBOX=1`、删除 `ELECTRON_RUN_AS_NODE`。渲染地址优先取 `ELECTRON_RENDERER_URL`，可用 `AI_BROWSER_RENDERER_URL` / `VITE_PORT` 覆盖，4 秒超时后回退到构建文件。

## 已知限制

- 资源分析只能看请求元数据，没有响应 body。
- 仅 Windows。
- 多用户隔离未实现。

## 下一步可选

- 响应体分析（需要 CDP `Network.getResponseBody`，会扩大 CDP 使用面）
- 多用户隔离（`session.fromPartition`，评估约 3–4 天）
- 下载、权限请求的应用内接管
