# Viewer 项目交接

> 新会话接手时先读这份文档和 `docs/DESIGN.md`，再继续开发。

## 目标

基于 Electron 做一个自定义浏览器：界面全部自绘，所有会和原生窗口交互的行为（alert/confirm/prompt、文件选择、新窗口、下载、权限等）由软件自身接管和监控，且不被网页发现。用于自有系统内部测试。

## 当前架构

```
应用窗口 (frame:false)
├─ 顶部单行工具栏：紧凑导航 ← → ↻ + 地址栏 + 窗口按钮
├─ 左侧：垂直标签页（每个标签 = 独立 WebContentsView）
├─ 中间：当前标签的网页 WebContentsView
├─ 光标层：透明 WebContentsView，仅 34×28，贴在网页上一层，画橙色虚拟光标
└─ 右侧：虚拟鼠标控制面板（X/Y、按键、连击、滚轮、显示开关）
```

## 已完成的约束

- 不用 Playwright/Puppeteer 内核；只用 Electron 自带 Chromium。
- 不往网页注入 JS（`executeJavaScript`/`eval`/`dispatchEvent` 都没有）。
- 不碰真实系统光标：已移除 koffi/SendInput，全部走 `sendInputEvent`，事件 `isTrusted=true`。
- `_blank` / `window.open` 转成新标签，不开新窗口。
- 虚拟光标：橙色、小巧、无文字；默认隐藏；窗口尺寸变化后自动隐藏；空白页不显示；每个标签独立状态。
- 点击分左键/右键，连击次数 1..10；有虚拟滚轮。
- 光标 View 只有 34×28 并跟随光标，真实鼠标在其余网页区域可正常 hover/滚轮。

## 原生交互接管（已实测）

- 文件选择：`Page.setInterceptFileChooserDialog` + `Page.fileChooserOpened` → 应用内文件选择器 → `DOM.setFileInputFiles`，实测回填成功（`count=1 name=interaction-test.html`）。注意必须由可信用户手势触发（虚拟鼠标点击即可），`executeJavaScript` 的 `input.click()` 不算。
- `alert` / `confirm` / `beforeunload`：暂不接管。WebContentsView 不提供阻止 Electron 默认弹框的接口，`js-dialog` 事件只在 `<webview>` guest 上触发；CDP 只能收到通知，无法阻止默认弹框。自绘弹框 UI 已按用户要求回退。
- `window.prompt`：Electron 官方不支持（渲染进程直接抛 `prompt() is not supported`），不产生 CDP 事件；在不注入页面 JS 的前提下无法接管。

下一步可选：把下载、权限请求等做成应用内 UI；JS 弹框若要接管需迁移标签页到 `<webview>`（官方不推荐，有稳定性警告）。

```bash

```

## 已知限制

- 光标 View 没有鼠标穿透 API（Electron 45 的 `WebContentsView` 不支持 `setIgnoreMouseEvents`），光标所在的 34×28 小块会拦截真实鼠标；其余区域正常。
- 虚拟光标输入走 `sendInputEvent`，不修改页面 DOM。
